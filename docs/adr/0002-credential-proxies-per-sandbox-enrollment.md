# ADR 0002: Credential proxies with per-sandbox enrollment, no forge tokens in the sandbox env

Status: accepted (2026-04-28)

Forge credentials never enter a sandbox's environment. Sandboxes reach the forge proxies (`git-proxy`, `github-proxy`, `gitlab-proxy`) by Docker DNS on the `sandbox-restricted` network; the proxy injects the orchestrator's token server-side. `auth-proxy` and `xai-proxy` follow the same pattern but are optional and off by default (`AUTH_PROXY_ENABLED`). Each sandbox is enrolled at launch and gets its own bearer token, so one sandbox's token cannot be replayed by another. The shared `PROXY_ADMIN_TOKEN` gates the proxies' `/admin/enroll` endpoints and is required in production. **Scoped exception:** `CLAUDE_CODE_OAUTH_TOKEN` (Claude Max mode) and non-Anthropic provider keys such as `XAI_API_KEY` are passed into the container env because the in-sandbox CLI and executor read them from the environment; [`docs/architecture.md`](../architecture.md) records this as a product constraint, and the command blocklist's environment-read patterns ([`embry0/safety/patterns.py`](../../embry0/safety/patterns.py)) are the compensating control. `EMBRY0_*_PROXY_URL`, `GITHUB_TOKEN`, `GITLAB_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `XAI_API_KEY` and the Anthropic variables are reserved keys, rejected as user-settable env vars at both the API and sandbox injection.
